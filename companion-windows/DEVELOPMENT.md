# ProfyPlan Companion — правила разработки

**Обязательно для любого изменения модуля.**

## 1. Где исходники

Все исходники companion — только в `profyplan/companion-windows/`. Не разносить по общим папкам API/web.

## 2. Что обновлять при каждом изменении

| Что изменилось | Обязательные файлы |
|---|---|
| Код, CLI, поведение обмена | `agent.py` (версия), `VERSIONS.md` (запись) |
| Архитектура, состав модуля, безопасность | `ABOUT.md` |
| Установка, параметры, быстрый старт | `README.md` |
| Планы и приёмка | общий `profyplan-план-реализации.md`, `profyplan-тест-план.md` |
| Пользовательское описание | общий промт `promt-profypyplan.md` |

## 3. Версионирование

- Semver: `0.x.y` до стабильного релиза.
- `0.x.0` — новая возможность; `0.x.y` — исправление/сборка.
- Версия в `agent.py` (`VERSION`) и `VERSIONS.md` должны совпадать.
- В `VERSIONS.md` — дата, статус, «Добавлено / Исправлено / Проверено / Ограничения».

## 4. Проверки перед коммитом

- [ ] `python -m py_compile agent.py`.
- [ ] `python agent.py --help`.
- [ ] `python agent.py status --config <test>`.
- [ ] `python agent.py once --config <test>` на локальном стенде.
- [ ] Проверить `in → processed` и `outbox → out/ack`.
- [ ] Проверить lease-конфликт (второй экземпляр → код 2).
- [ ] `install.ps1 -NoTask` проходит.
- [ ] При изменении сборки — `build.ps1` и запуск EXE.
- [ ] Нет секретов в коде/конфиге/логах.

## 5. Коммиты

- Код: `feat(companion): ...` или `fix(companion): ...`.
- Документы: `docs [skip ci]: ...`.
- В одном коммите или в связанной паре — `VERSIONS.md` и общий план/тест-план.

## 6. Безопасность

- Пароль/токен — только DPAPI или защищённое хранилище.
- Не логировать пароль, JWT и содержимое файлов.
- Не открывать входящие порты.
- Работать только с выбранной папкой.
- EXE для клиента — только подписанный.
