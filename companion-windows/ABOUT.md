# ProfyPlan Companion — описание модуля

**Версия:** 0.8.2 · **Статус:** Windows MVP · **Дата:** 22.10.2026
**Папка исходников:** `profyplan/companion-windows`
**История версий:** [VERSIONS.md](VERSIONS.md) · **Правила разработки:** [DEVELOPMENT.md](DEVELOPMENT.md)

## 1. Назначение

Companion — универсальный программный модуль файлового обмена между ProfyPlan и внешними учётными системами, без браузера и без расширения. 1С:УНФ — первый подключаемый коннектор, но модуль не привязан к 1С. Он читает папку `in`, отправляет пакеты в ProfyPlan, забирает `outbox` в `out`, переносит обработанное в `processed` и ведёт журнал.

Основной сценарий — машина, где лежит папка обмена: рабочая станция пользователя, сервер учётной системы или выделенный компьютер обмена.

## 2. Почему отдельный модуль

- Работает без открытого браузера и по расписанию.
- Видит локальные и сетевые папки (UNC), куда расширение не достанет.
- Один модуль закрывает Windows, а в перспективе — macOS.
- Не зависит от Chrome Web Store и режима разработчика.
- Может развивать собственные транспорты: файл, облако, FTP, почта.

Расширение Chromium остаётся дополнительным «lite»-режимом для одного пользователя; публикация в магазинах отложена (см. `docs/backlog/extension-store/`).

## 4. Архитектура

```
[Учётная система / папка in] → Companion (agent.py)
                    ├─ login → ProfyPlan API
                    ├─ lease (один обмен на подключение)
                    ├─ import-file → очередь ProfyPlan
                    ├─ outbox → файлы в out
                    └─ processed / state.json / companion.log
[ProfyPlan plan] → outbox → Companion → [папка out] → учётная система
```

- **Auth:** основной режим — pairing-код → агентский токен (DPAPI); fallback — email/пароль → JWT.
- **Lease:** `POST /v1/integration/connections/{id}/lease`, TTL 120 c; второй экземпляр получает 409.
- **Входящие:** `import-file` (multipart), после успеха файл переносится в `processed`, ключ пишется в `state.json`.
- **Исходящие:** `outbox` → `files/{name}` → запись в `out` через `.part` + `os.replace` → `ack`.
- **Идемпотентность:** ключ `имя|размер|mtime` + серверный `packet_id`.
- **Логи:** `companion.log` рядом с папкой обмена, ротация 2 МБ × 3.

## 5. Режимы CLI

| Команда | Что делает |
|---|---|
| `init` | мастер: API, email, пароль, подключение, папка (fallback) |
| `pair` | привязка по одноразовому коду из ProfyPlan, без пароля |
| `once` | один цикл обмена (для проверки и задач) |
| `run` | цикл с интервалом |
| `tray` | иконка в трее + фоновый цикл |
| `setup/install` | установка и автозапуск (для Setup EXE) |
| Настройки в трее | отдельное окно, не Notepad |
| `status` | показать настройки и число файлов в `in` |

## 6. Безопасность

- Пароль шифруется Windows DPAPI; в конфиге нет открытого пароля.
- Соединение только HTTPS (HTTP допускается для локального стенда).
- Companion не слушает входящие порты.
- Работает только с `in/out/processed` выбранной папки.
- Токен доступа живёт в памяти, не пишется в конфиг.
- Для клиента EXE должен быть подписан код-сертификатом; иначе SmartScreen предупреждает.

## 7. Ограничения текущей версии

- Нет pairing-кода: используется email/пароль + DPAPI.
- Нет серверной службы без входа пользователя.
- Нет macOS-версии.
- EXE не подписан.
- Установщик — self-install EXE; MSI/подпись — следующие.
