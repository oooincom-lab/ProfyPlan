## 3. РАСХОЖДЕНИЯ ДОКУМЕНТ ↔ КОД

Формат: **что обещает документ → что реально в коде → вывод.**

**R1. Распределение в Монте-Карло.**
- Документ: Продукт §2.4/§3.3/§11 п.5 — «треугольное `numpy.random.triangular(to, tm, tp)`» (PERT-бета — вскользь).
- Код: `apps/api/app/services/pert_monte_carlo.py` — бета-PERT (`_sample_beta_pert(o, ml, p)`, α=1+4(ml−o)/(p−o), β=1+4(p−ml)/(p−o)); `numpy` не подключён (`import random`).
- **Вывод:** расхождение. Код использует бета-PERT, а не треугольное; `numpy`-функции не используются.

**R2. Предупреждение о расхождении медианы (>5%).**
- Документ: §2.4/§3.3 — предупреждение при |медиана − TE_project| / TE_project > 5%.
- Код: в `run_monte_carlo` предупреждения только при отсутствии PERT-оценок; сравнения с TE и порога 5% нет.
- **Вывод:** заявленная проверка не реализована.

**R3. Несколько критических путей (σ = max ΣV).**
- Документ: §3.3 — при нескольких критпутях σ_project = max по путям.
- Код: `calculate_pert` суммирует дисперсии по одному пути из `cpm_result.critical_path`; max по ветвям (`critical_paths`) не берётся.
- **Вывод:** правило «консервативной оценки» не реализовано.

**R4. Выравнивание ресурсов: CP-SAT против Serial SGS.**
- Документ: §3.4 — двухфазный алгоритм: «Фаза A — CP-SAT (`ortools.sat.python.cp_model`)», Serial SGS — фаза B.
- Код: `apps/api/app/services/resource_leveling.py` — «Serial SGS алгоритм выравнивания ресурсов»; grep `ortools|cp_sat|cp_model` по `services/*.py` и `routers/*.py` — 0 совпадений.
